# DECISIONS.md — Spigot-Dashboard

Why this repo looks the way it does. Newest first.

**Read the "Tried and rejected" table at the bottom before proposing anything.**

**When to add an entry:** a session made a real choice — rejected an alternative, hit a
constraint that shaped the design, or reversed an earlier decision. Not for mechanical work.
If you cannot fill in **Why**, there is no entry to write.

**Format:**

```markdown
## YYYY-MM-DD — one line, what changed

**Decided:** what was done.
**Why:** the problem, with the evidence that proved it (command + output, number, file:line).
**Rejected:** what else was considered, and what killed it. Omit if nothing was.
**Files:** paths.
**Ref:** commit hash, or "uncommitted". Agents always write "uncommitted"; the user fills the hash when signing.
```

## 2026-09-20 — Merge with `origin/main`: three files resolved to this branch, and why

**Decided:** Merging `f256364` into this branch conflicted on `src/auth/SignInModal.tsx`, `src/credits/TopUpPanel.tsx` and `src/views/Profile.tsx`. All three resolve to this side. That drops the client-side Algorand USDC opt-in UI added in `f256364` (an "Opt-In Needed" badge and an activate button in `TopUpPanel` and `Profile`) and the inline sign-in form rewritten in `e512cba`. The images in this branch also moved from PNG to WebP.

**Why:** Two people edited the same three files, which is the case rule 3.3 exists to prevent; recording the reasoning here matters more than usual, because the other person's committed work is being set aside. The user was shown the conflict and chose this resolution. Three things support it. **First, the opt-in button is superseded by its own author's later backend commits.** `Spigot-Algorand/backend/src/services/treasury.ts:961` now reads `if (!balances.optedIn) await provisionWallet(wallet)` inside `ensureAlgorandUserFloat`, which `routes/consume.ts` calls on the paid-call path, and `provisionWallet` is documented at `treasury.ts:238` as "safe to run repeatedly — it does nothing once the opt-in exists". The server opts the custodial wallet in by itself, so a button asking the caller to do it is work the backend already did. **Second, the dropped UI contradicts a product rule the user gave in the same session:** it put "Algorand" and "ASA 10458941" in front of a caller, and the surfaces it lived on were removed precisely because a caller is never told which chain holds their credit. It also called `https://testnet-api.algonode.cloud` straight from the browser and built opt-in transactions with `algosdk` client-side, which is a different trust shape from every other call in this app. **Third, `SignInModal` lost nothing.** `e512cba` added a one-click testnet sign-in to the inline form that this branch had already moved into `SignInPanel.tsx`, and that panel has carried the same capability since earlier the same day: `handleDevSignIn` at `SignInPanel.tsx:197` requests the backend's dev magic link and navigates, behind the "Skip sign-in as …" button at `:388`. Taking the other side would have restored a second copy of the whole form, which `local/ux-checklist.md` records as already fixed under "the modal and `/login` are the same form, not two". `npm run verify` exits 0 on the merged tree and the review prints 16 passed, 0 failed, 0 unverified.

**Rejected:** taking `origin/main` for `TopUpPanel.tsx` and `Profile.tsx` (it would undo the add-credit modal and the de-jargoned account page, both built to explicit direction, to restore a button the backend has made unnecessary); keeping both by porting the opt-in UI into the new modal (it names the chain to the caller, which is the thing the rewrite removed); re-adding a chain-free "activate your account" control now (offered to the user and not taken — the backend opts in on the consume path, so there is nothing for the caller to fix, and a control that fires on a failure that cannot happen is dead code).

**If the opt-in is still needed:** the evidence above says it is not, but it was not tested against a wallet that had never been opted in. If a top-up does fail that way, `authApi.activateWallet` is still defined in `src/api/auth.ts` and calls the backend, so the fix is a control on this side rather than a revert of the merge.

## 2026-09-20 — The chain leaves the caller's screen; one control per job

**Decided:** The "Where the money is held" disclosure is deleted from `/profile`, which is now balance, Add credit, Activity and Sign-in at 203 lines. `src/views/ConsumerTest.tsx` loses its "the gateway settles the payment on Algorand", its "you never need ALGO", its "network fee paid by the facilitator", its nine-option Settlement Chain picker and the network name on its receipt, and it no longer sends a `chain` with the call. On the caller overview, the account menu's "Account & credit" item is gone, and the banner's "Add credit" opens the top-up modal in place rather than routing to `/profile`. `AddCreditModal` is exported from `src/credits/TopUpPanel.tsx` for that. `formatCredit` is added to `src/lib/format.ts`.

**Why:** The user gave the rule and it is worth recording verbatim in substance: a caller recharges, the funds land in an account Spigot controls, the backend credits a custodial account the caller cannot withdraw from, and they are never told which chain any of it is on. The previous pass had folded the chain cards into a closed disclosure, which was the wrong compromise under that rule, so they are deleted. The call page mattered more than it looked: its Settlement Chain picker was not only vocabulary a caller cannot act on, it was a defect. `Spigot-Algorand/backend/src/routes/consume.ts:130` reads `let targetChain = chain` from the request body and only falls back to the publisher's payout wallet when that is absent, so a picker sitting on its "Algorand" default silently overrode where the publisher had asked to be paid. Sending no `chain` is what restores the publisher's choice. Separately the user pointed at the overview offering the same destination three times, which it did: the sidebar row, the account menu item and the banner button all pushed `/profile`. The menu keeps what only it can do, identity and sign out; the sidebar keeps the navigation; and the button now does what its label says, which also saves a page load, because `CallerView` has already fetched the `overview` the modal needs. `formatCredit` exists because the same balance was rendering at three precisions on one screen, and the account menu managed two of them by itself: `$0.00` on the chip and `$0.000000` in the panel it opened. Four places is the right number, since calls are priced below a cent and a balance rounded to `$0.00` reads as empty when it is not. Checked in a browser: `/profile` shows four cards and no chain; the overview's Add credit opens the modal with no navigation; the account menu reads "Signed in as / Credit $0.0000 / Sign out"; and exactly one "Account & credit" control is on the screen. `grep -rniE "algorand|solana|stellar|usdc|on-chain|blockchain|x402"` over the three caller files returns one hit, the `amountUsdc` field name in a receipt that renders as `$<number>`. `npm run verify` exits 0 and the review prints 16 passed, 0 failed, 0 unverified.

**Rejected:** keeping the chain accounts behind a disclosure (the compromise from the previous entry, reversed here at the user's direction: the rule is that the caller is never told, and a disclosure still tells them); removing "Account & credit" from the sidebar instead of the menu (the caller sidebar would be a single row, and the menu is the one control that works on pages with no sidebar, so it keeps sign-out); leaving `chain` in the consume request now that the picker is gone (it would have pinned every call to "Algorand" and gone on overriding the publisher's payout wallet); applying `formatCredit` to every money figure in the app (revenue, settlement and quote figures are different numbers on different screens, and changing them was not asked for, so they are recorded as open instead).

**Not checked in a browser:** `/test/<slug>` needs a published API, and this checkout is two commits behind the seeder that creates one. The change there is a deletion plus dropping one request field, and `npm run verify` covers the compile.
